# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ АВТОНОМНОГО АГЕНТА: ОБНОВЛЕНИЕ «ШКОЛА ДРОП» v3.5 & v3.6 BETA

## 1. КОНТЕКСТ И ОГРАНИЧЕНИЯ СРЕДЫ
- **Среда выполнения:** Автономный агент (Agent Mode) с доступом к bash/terminal, локальной файловой системе и GitHub CLI / Git.
- **Сетевые ограничения:** Прямого доступа во всемирный интернет нет (только локальный репозиторий и git push/pull). Все библиотеки, ассеты и логика должны быть либо уже в проекте, либо генерироваться локально без внешних fetch-запросов к сторонним API.
- **Первый шаг перед работой:** Обязательно исследуй структуру проекта через терминал (`ls -la`, `find .`, `grep -rn "version"`), определи разделение на JS-модули и HTML, чтобы не затереть существующий функционал (VIP-коды, котики, рулетки).

## 2. ОСНОВНЫЕ ЗАДАЧИ

### Задача 1: Обновление версии проекта до v3.5 (Stable)
1. Найди все места упоминания старых версий (в UI, шапке, футере, `package.json`, мета-тегах и тайтле).
2. Зафиксируй стабильную версию: **3.5** (Сезон 3, версия 3.5).
3. Добавь стильный бейдж версии в шапке сайта: `v3.5 Stable`.

---

### Задача 2: Прелоадер (Экран загрузки ресурсов при входе)
**Проблема:** При нестабильном соединении или медленной подгрузке CDN сайт иногда рендерится рывками до загрузки всех стилей и скриптов.
**Решение:**
1. Добавь полноэкранный стильный Splash Screen (экран загрузки), который скрывает основной интерфейс до полной готовности DOM и скриптов (`window.addEventListener('load', ...)`).
2. На экране загрузки должны быть:
   - Логотип проекта с плавной пульсацией.
   - Анимированный Progress Bar (0% -> 100%).
   - Меняющиеся школьные статусы загрузки (каждые 400–600 мс):
     - *«Проверяем сменку на входе...»*
     - *«Подгружаем свежие котлеты из буфета...»*
     - *«Обходим дневник русички...»*
     - *«Инициализация модулей v3.5...»*
3. После завершения экран плавно исчезает (`opacity: 0`, `pointer-events: none`) с анимацией fade-out.

### Задача 3: Режим «3.6 Beta» (Бета-тестирование) в Настройках

#### 3.1. Интерфейс переключения в Настройках:
- В модальном окне настроек (Settings / Профиль) в самом низу добавь секцию:
  - Заголовок: **«Лаборатория / Бета-тестирование»** (с бейджем `BETA 3.6`).
  - Описание: *«Получи доступ к экспериментальным кейсам и новым механикам до официального релиза.»*
  - Тумблер / кнопка: **«Включить 3.6 Beta»**.

#### 3.2. Механика перехода в Бету (Имитация загрузки обновления):
1. При нажатии на тумблер **не переключать мгновенно**:
   - Блокируется интерфейс и открывается экран загрузки обновления:
     - *«Подключение к тестовой ветке 3.6 Beta...»*
     - Прогресс-бар скачивания пакетов обновления (2.5–3 секунды).
     - Текст: *«Распаковка экспериментальных кейсов и конфигов...»*
2. Состояние сохраняется в `localStorage` (флаг `isBetaMode: true`).

#### 3.3. Логика профиля и никнейма:
- **При входе в 3.6 Beta:**
  - Текущий никнейм игрока временно бэкапится (например, в ключ `savedRealNickname`).
  - Текущий никнейм принудительно заменяется на: **`Тест`** (или `Тестер`).
  - В шапке появляется яркий неоновый индикатор: `v3.6 BETA TESTING`.
- **При выключении беты (возврат в v3.5):**
  - Никнейм автоматически восстанавливается из бэкапа на старый никнейм игрока.
  - Индикатор возвращается на `v3.5 Stable`.

#### 3.4. Особенности режима v3.6 Beta (Контент беты):
1. **Экспериментальные кейсы:**
   - Добавь 2–3 новых бета-кейса (например, *«Кейс Кибер-Кота 3.6»*, *«Тайник Физика-Ядерщика»*).
   - На них должна висеть плашка `🧪 ЭКСПЕРИМЕНТАЛЬНО`.
2. **Функции в разработке:**
   - Добавь 1–2 кнопки/карточки будущих функций с ярлыком `[В разработке]` (например, *«Школьные кланы»* или *«Крафт-лаборатория»*), при клике на которые всплывает уведомление: *«Функция тестируется в закрытом режиме 3.6!»*.
3. **Фокус на новом:** Часть старых стандартных кейсов в режиме беты можно скрыть или свернуть в категорию «Архив», чтобы на первом плане был только новый бета-контент.

## 3. ТРЕБОВАНИЯ К КОДУ И БЕЗОПАСНОСТИ
1. **Изоляция состояния:** Не ломать существующий `localStorage` (баланс, инвентарь и уже активированные VIP-коды должны сохраняться корректно при переключении версий).
2. **Чистая архитектура:** Если в проекте уже есть модульная структура (`src/`, `js/`), вынеси логику беты в отдельный модуль (например, `betaManager.js` или расширь `settings.js`), а экран загрузки в `preloader.js`.
3. **Тестирование:**
   - Запусти проект локально (через встроенный HTTP-сервер, live-server или node) и проверь отсутствие JS-ошибок в консоли.
   - Проверь переключение тумблера: Вкл -> загрузка -> смена ника на «Тест» -> Выкл -> возврат старого ника.
4. **Git коммит:**
   - Выполни понятный коммит:
     `git commit -m "feat(core): release v3.5, add preloader and v3.6 beta testing mode"`
   - Отправь изменения в ветку: `git push origin main`.
