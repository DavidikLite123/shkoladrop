## 1. Что было не так

Проект — браузерная игра: всё, что нужно браузеру, игрок может скачать. А хостинг раздавал
**весь корень репозитория**:

| Что утекало | Где это было видно |
|---|---|
| Код владельца `1337`, код админа `7331`, секреты `david-admin-1337` / `david-staff-7331` | `shkoladrop.vercel.app/codes/admin-codes.md` **и** `shkoladrop.onrender.com/codes/admin-codes.md` |
| Все 100 VIP-кодов открытым текстом (это 15 000 ₽ товара) | `shkoladrop.vercel.app/codes/vip-codes.md` |
| Реестр авторов, тесты, исходники сервера, README, package.json | те же два домена |

Дополнительно: сервер доверял `uid`, который присылает клиент, — можно было скачать и
перезаписать чужой облачный сейв, а через `/api/account/start` привязать свою почту к
чужому профилю.

## 2. Что уже сделано в этом обновлении

- **Статика закрыта.** И Vercel (`.vercelignore`), и Node-сервер (`server/index.js` →
  белый список `index.html`, `manifest.webmanifest`, `css/`, `js/`, `assets/`) отдают
  только саму игру. Публикация `codes/`, `docs/`, `tests/`, `server/`, `author-codes.json` — 404.
- **Секретов в клиенте больше нет.** Из `js/config.js` удалены коды и серверные секреты,
  удалён `betaCodeHash`. Панель теперь логинится **на сервере**: `POST /api/admin/login {code}`
  → подписанный токен роли на 12 часов → заголовок `x-admin-token`. В браузере хранится только
  этот токен; украсть нечего, без верного кода его не выдают, антибрутфорс — 10 попыток за 10 минут.
- **Старые коды/секреты мертвы.** `1337`, `7331`, `david-admin-1337`, `david-staff-7331`
  больше не работают нигде.
- **Опубликованные VIP-коды аннулированы**, выпущены новые (`node tools/rotate-vip-codes.js`),
  список лежит в `vip_codes_funpay.txt` — этот файл в `.gitignore` и в деплой не попадает.
- **Данные больше не теряются.** Появился внешний «сейф» (`server/vault.js`): база уезжает
  в приватный GitHub-репозиторий (или HTTP-хранилище) и восстанавливается, если Render
  стёр диск. Пустая база сейф не затирает — проверено тестом `tests/vault.test.js`.
- **Тесты:** `tests/server-security.test.js` (27 проверок) и `tests/vip-rotate.test.js`
  (20 проверок) следят, чтобы утечки не вернулись.

## 3. Что осталось нажать руками (по шагам)

### Шаг 1. Render → Environment (обязательно)

Открой Render → свой сервис → **Environment** и добавь:

| Переменная | Значение |
|---|---|
| `OWNER_ADMIN_CODE` | новый код владельца, например `KOT-8K2M-P9` (придумай сам) |
| `STAFF_ADMIN_CODE` | новый код админов |
| `SESSION_SECRET` | любая длинная случайная строка (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`) |
| `SHKOLA_VAULT` | `github` (см. шаг 2) |
| `SHKOLA_VAULT_REPO` | `DavidikLite123/shkoladrop-vault` — **приватный** репозиторий |
| `SHKOLA_VAULT_TOKEN` | fine-grained токен GitHub с правом *Contents: Read and write* на этот репозиторий |
| `SHKOLA_VAULT_PATH` | `shkola-db.json` (необязательно) |
| `ADMIN_SECRET` / `STAFF_SECRET` | необязательно: нужны только если где-то дергаешь API скриптами |

Если ничего не задать, сервер сгенерирует коды сам и **напечатает их в логах** —
но менять их будет при каждом рестарте, так что лучше вписать в env.

### Шаг 2. Приватный «сейф» для базы

1. Создай **приватный** репозиторий, например `shkoladrop-vault` (без файлов).
2. GitHub → Settings → Developer settings → **Fine-grained tokens** → новый токен,
   доступ только к этому репозиторию, право **Contents: Read and write**.
3. Вставь токен в переменную `SHKOLA_VAULT_TOKEN` на Render (шаг 1).

Теперь каждые ~20 секунд база уезжает в сейф, а при старте сервер её оттуда поднимает,
если диск Render пустой. Проверить можно так: в игре в админке вызвать
`GET /api/admin/vault/status` — там видно, включён ли сейф, когда была последняя запись и сколько попыток.
Ручной «сохранить сейчас» — `POST /api/admin/vault/flush`.

### Шаг 3. Vercel (сайт)

1. Сделай репозиторий **private** — деплой Vercel/Render продолжит работать (доступ через GitHub App).
2. Передеплой сайт на Vercel, чтобы уехали `.vercelignore` и новые `js/`.
3. **Удали старые деплои** Vercel (Project → Deployments → у каждого старое меню → Delete):
   старые URL вида `shkoladrop-xxxx.vercel.app` иначе продолжат отдавать утёкшие файлы.

### Шаг 4. Проверка (2 минуты)

```bash
# на сайте: должно быть 404
curl -I https://shkoladrop.vercel.app/codes/admin-codes.md
curl -I https://shkoladrop.onrender.com/codes/admin-codes.md

# на сервере: старый код не пускает, новый — пускает
curl -X POST https://shkoladrop.onrender.com/api/admin/login -H 'Content-Type: application/json' -d '{"code":"1337"}'
curl -X POST https://shkoladrop.onrender.com/api/admin/login -H 'Content-Type: application/json' -d '{"code":"ТВОЙ_НОВЫЙ_КОД"}'
```

Вход в панель: 5 кликов по логотипу → ввести `OWNER_ADMIN_CODE`. Либо промокодом `ADMIN<код>`.
Панель требует интернет — роль выдаёт сервер.

### Шаг 5. VIP-коды

Список новых кодов — в `vip_codes_funpay.txt` (в git не попадает, лежит только у тебя).
Продаёшь по 150 ₽, выдаёшь по порядку и отмечаешь в таблице. Если список утечёт снова:
`node tools/rotate-vip-codes.js` выпустит новые, а старые мгновенно перестанут работать.

## 4. Что ещё стоит сделать (не срочно, но важно)

- **Приватность сервера и регистрация:** `/api/save` и `/api/account/start` всё ещё верят `uid`
  из запроса — то есть чужой прогресс можно прочитать. Следующий шаг: после `/api/account/verify`
  сервер выдаёт токен игрока, и «мои» ручки (`/api/save`, `/api/royalty`, `/api/gifts`, `/api/trades`)
  работают только с ним. Тогда и захват аккаунта закрывается окончательно.
- **Пароли:** SHA-256 + соль лучше заменить на `scryptSync` (встроен в Node, зависимостей не нужно).
  Миграция делается прозрачно: при следующем входе пароль перехешируется.
- **Рейт-лимиты** на чат, подарки и трейды (сейчас лимит есть только на вход в админку).
- **`clientIp()`** доверяет заголовку `X-Forwarded-For` без проверки хопов — IP-бан сейчас
  обходится; на Render трафик идёт через их прокси, стоит ограничить доверенные хопы.
